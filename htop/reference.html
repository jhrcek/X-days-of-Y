Everything, on one page

Every key, command and option introduced by the course, with the day it first appears. This is the page to keep open while the habits settle.

Keys

Commands

CommandDoesDay
htopStart htop, reading ~/.config/htop/htoprc once at startup.1
htop -d 10Sample every 10 tenths of a second. Clamped to the range 1–100.1
htop -n 5Draw five frames, then exit on its own. Absent from the manual page.1
htop -VPrint the version. The -v in the SYNOPSIS does not exist.1
htop -F chromeStart with the filter already applied. Multiple terms: -F 'nginx|php'.4
htop -p 1,843Show only these PIDs, and nothing else ever appears.4
htop -uShow only your own processes.4
htop -u postgresShow one user's processes. A numeric UID works too.4
htop -s PERCENT_MEMStart sorted by a column. Forces list view.5
htop -s PERCENT_MEM -tSorted and in tree view — the one way to have both.5
htop --sort-key helpPrint every sortable column name and what it means.5
htop -t=softTree view with a stable cursor line. classic, soft and hard, or 0/1/2.5
htop --readonlyDisable every process- and system-changing feature for this session.6
htop --no-metersStart with the header hidden. Gives the process list the whole terminal.8
htop -CMonochrome. The bar segments become bold, normal and dim instead of colours.8
htop -UASCII instead of unicode for the graph meters.8
HTOPRC=~/x htopRead (and write) a different config file. One config per machine, one shared home directory.9
chmod 444 ~/.config/htop/htoprcMake the file read-only. htop then runs normally and stops clobbering it.9
htop --sort-key helpThe authoritative column list, straight from the binary. Better than the manual page.10
htop --drop-capabilities=strictShed Linux capabilities at startup. Kills renicing and delay accounting with them.14
pcp-htopA different binary: htop over Performance Co-Pilot metrics. Its own manual page, pcp-htop(5).14

Options

OptionDoesDay
delayTenths of a second between samples in htoprc. Default 15, i.e. 1.5 s.1
M_VIRTAddress space the process has mapped. VIRT. Mostly promises, not memory.3
M_RESIDENTPages actually in RAM, shared ones counted in full. RES.3
M_SHAREThe part of RES that other processes also map. SHR.3
M_PRIVResident minus shared — what dies with the process. PRIV, a default column.3
M_SWAPPages of this process pushed out to swap. SWAP.3
M_PSSResident, but each shared page divided by its number of sharers. PSS.3
M_PSSWPThe same proportional treatment for swapped-out pages. PSSWP.3
M_EPSSPSS plus PSSWP: the whole footprint, proportionally. EPSS.3
PERCENT_MEMRES as a share of total RAM. MEM% — and it inherits RES's double counting.3
detailed_cpu_timeSplit the CPU bar into irq, soft-irq, steal, guest and io-wait. Default off.8
header_layoutOne to four columns, in fourteen width presets. Default two_50_50.8
column_meters_0The meters in the first header column, space-separated.8
column_meter_modes_0Their display modes: 1 bar, 2 text, 3 graph, 4 LED.8
highlight_changesHighlight processes that are new or whose command line changed. Default off.9
highlight_changes_delay_secsHow long that highlight lasts. Default 5.9
enable_mouseLet htop capture mouse events. Default on, which costs you terminal text selection.9
header_marginLeave a blank line around the header. Default on.9
screen_tabsShow the names of screen tabs above the list. Default on.9
fieldsThe legacy numeric column list. Silently overrides every screen: line.9
NLWPHow many threads this process has. The cheapest way to spot a thread pool.10
TGIDThread group id — a thread's process. Equals PID for a process.10
STARTTIMEWall-clock time the process started. Shown as START.10
ELAPSEDHow long it has been running. Undocumented in the manual page.10
OOMThe OOM killer's score for this process. Who dies first under memory pressure.10
CTXTContext switches counted over the refresh interval. A rate, not a lifetime total.10
PROCESSORWhich CPU it last ran on. Shown as CPU.10
SCHEDULERPOLICYThe scheduling policy from Day 6's Y dialog. Undocumented in the manual page.10
SECATTRThe SELinux or AppArmor label. Undocumented, and very wide.10
show_thread_namesShow each thread's own name rather than its process's command. Default off.10
highlight_threadsDraw thread rows in a different colour. Default on.10
screen:NAMEDefine a screen and its columns, in order, space-separated.11
.sort_keyThe sort column for the screen defined immediately above.11
.sort_direction-1 for descending, 1 for ascending.11
.tree_viewWhether this screen starts in tree view. Per-screen, like everything dotted.11
RCHARBytes the process has read through read(). Counts cache hits — most of this never touched a disk.12
WCHARBytes written through write(). Counted when the call returns, not when the data lands.12
RBYTESBytes actually fetched from the block layer. Real disk reads.12
WBYTESBytes actually sent to the block layer.12
CNCLWBWrite bytes cancelled — dirtied, then truncated or deleted before writeback.12
IO_READ_RATEBlock-layer read rate. Shown as DISK READ.12
IO_WRITE_RATEBlock-layer write rate. Shown as DISK WRITE.12
IO_RATEThe two rates added. Shown as DISK R/W, and the right default sort for an I/O screen.12
IO_PRIORITYScheduling class and priority: R realtime, B best-effort, id idle.12
PERCENT_IO_DELAYShare of time blocked on synchronous block I/O. Needs delay accounting.12
PERCENT_CPU_DELAYShare of time runnable but not scheduled. The number that proves CPU contention.12
PERCENT_SWAP_DELAYShare of time waiting for pages to swap back in.12
CGROUPThe full cgroup path. Displayed as CGROUP (raw), and far too wide to keep on screen.13
CCGROUPThe same path, compressed by ten rules. Displayed as CGROUP (compressed).13
CONTAINERThe container's name, guessed by heuristics. Undocumented in the manual page.13
ISCONTAINERWhether the process is inside a child container. Undocumented too.13
