From “a nicer git log” to staging single lines, writing your own keymaps, and driving tig from external commands that know which commit you are looking at. One sitting a day, each small enough to actually use at work the same afternoon.

How to use this

One sitting a day

Each lesson introduces a handful of concepts and stops. The drills at the bottom are the actual lesson — tig is muscle memory, and reading about u on a diff chunk teaches you nothing. Do the drills in a repository whose history you already know.

Replace one habit on Day 1

Every time you would have typed git log, type tig instead. That single substitution carries the first six days; everything after is refinement of a habit you already have.

Build your own tigrc

From Day 7 each lesson adds a few justified lines to ~/.tigrc. Nothing is pasted from a stranger's dotfiles: by Day 14 you can defend every line. The finished file is here.

The syllabus

  1. 01

    The viewer model

    A view is a git command's output, and views live on a stack.

    viewsview stackbrowsing state
  2. 02

    The main view

    The graph, the refs, and three rows that are not commits.

    main viewgraphtoggles
  3. 03

    Moving between views

    Parent and child, the view stack, and why the arrow keys are not j and k.

    split viewnavigationstack
  4. 04

    Reading diffs

    Context, chunks, and the filter you did not know was on.

    diff viewchunksfilters
  5. 05

    Finding things

    Search and the prompt are two different ways to move.

    searchpromptgoto
  6. 06

    Staging from the diff

    Stage the file, the chunk, the part, or the single line you actually meant.

    status viewstage viewchunks
  7. 07

    Options and your first tigrc

    A setting is the same thing at the prompt and in the file.

    tigrcsettoggles
  8. 08

    Files through time

    Tree to blob to blame, and walking back past the change you found.

    treeblobblame
  9. 09

    Refs, stashes and the reflog

    The views that browse names instead of history — and the keys that act.

    refsstashrefloggrep
  10. 10

    The command line

    Revision specification, path limiting, and tig as a pager.

    revisionspager modesubcommands
  11. 11

    Columns and view settings

    A view is a list of column specifications, and each one is addressable.

    columnsview settingslayout
  12. 12

    Bindings and keymaps

    Key resolution runs view, then generic, then built-in.

    bindkeymapsactions
  13. 13

    External commands

    Command flags, plus your browsing state substituted in.

    external commands%(variables)flags
  14. 14

    Colours and sharp edges

    Areas, large repositories, and every place the manual is wrong.

    colourperformanceenvironment

What is deliberately left out

The full seventy-entry colour-area table, the complete list of browsing-state variables, the testing hooks (TIG_NO_DISPLAY, :save-view), the pgrp option and its Zsh interaction, and the deprecated v1 commit graph. By Day 14 you can read tigrc(5) for those yourself — which is the real skill on offer here.
